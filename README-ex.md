# CPA Usage Keeper-EX 主要能力

本页只列相对上游 Usage Keeper 的主要功能。上游能保存 CPA 用量并展示基础统计，但当一个部署同时服务多个凭证、渠道和价格规则时，成本归属会失真；本 fork 把价格、身份和证据链补齐。

- **分层定价体系**：上游价格主要按模型或 Provider 解释，难以表达不同凭证的默认倍率、模型例外和固定资费。本 fork 支持凭证默认价、指定模型倍率、固定资费，并把规则写入请求和窗口的价格快照。
- **渠道与成员价格**：上游缺少面向团队或渠道的独立价格边界。本 fork 支持命名渠道、渠道成员、模型倍率和固定价格，让同一 CPA 的不同使用主体可以分别核算。
- **官方目录与凭证价格矩阵**：上游模型价格来源和凭证实际覆盖范围不够清晰。本 fork 引入官方模型价格目录与凭证模型价格矩阵，保留刷新、迁移和回滚证据，避免历史数据因价格更新而漂移。
- **双成本估算与可解释差异**：上游通常只给出一套成本，凭证信息不完整时无法解释为什么对不上。本 fork 同时展示官方/有效规则两套估算，并说明凭证主体不足、渠道覆盖或价格缺失造成的差异。
- **主体同步与隐私标签**：上游凭证主体可能滞后，界面标签也容易暴露密钥片段。本 fork 自动同步凭证主体，只显示掩码后的密钥提示，并把定价规则绑定到可验证的身份迁移结果。
- **持久化分析与实时视图**：上游的历史、实时和额度视图彼此割裂。本 fork 将价格矩阵接入请求明细、实时面板、窗口统计和排行榜，使一次请求在不同视图中保持同一套解释。

本页只说明 EX fork 的增量；部署、配置和 CPA 接入要求仍以仓库正文为准。
